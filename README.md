# Employee Management System

A RESTful Employee Management System built with **Java 21**, **Spring
Boot**, **Spring Data JPA**, and **MySQL**. The application provides
APIs to create, retrieve, update, and delete employee records.

## Features

-   Create an employee record.
-   Retrieve all employee records.
-   Retrieve an employee by ID.
-   Update an existing employee.
-   Delete an employee by ID.
-   Delete all employee records.
-   Validate employee input using Jakarta Bean Validation.
-   Handle common API errors through a global exception handler.
-   Persist employee data in MySQL using Spring Data JPA.

### Layer responsibilities

-   **Controller:** Exposes the REST endpoints under `/details` and
    passes requests to the service.
-   **Service:** Contains the employee create, read, update, and delete
    operations.
-   **Repository:** Extends `JpaRepository<Employee, Integer>` to
    provide database operations.
-   **Entity:** Maps the `Employee` class to a database table.
-   **Exception handler:** Formats validation, malformed JSON, type
    mismatch, and data-integrity errors into HTTP responses.

## Database Configuration

The project is configured to connect to a local MySQL database named
`EmployeDb`.

Update `src/main/resources/application.properties` for your own
environment:

``` properties
spring.application.name=employeemanagement_system
server.port=1521

spring.datasource.url=jdbc:mysql://localhost:3306/EmployeDb?createDatabaseIfNotExist=true
spring.datasource.username=${DB_USERNAME}
spring.datasource.password=${DB_PASSWORD}

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
```

Set the `DB_USERNAME` and `DB_PASSWORD` environment variables before
starting the application. Do not commit real database passwords or other
secrets to GitHub. The uploaded project configuration contains a
database password; rotate it if it has ever been pushed to a public or
shared repository, and remove it from the source configuration and Git
history as appropriate.

`spring.jpa.hibernate.ddl-auto=update` lets Hibernate update the schema
based on the entity mapping. For production deployments, use a
controlled database migration approach.

## REST API Endpoints

Base URL:

``` text
http://localhost:1521/details
```

  Method     Endpoint          Description                   Request body
  ---------- ----------------- ----------------------------- ---------------
  `POST`     `/details`        Create an employee            Employee JSON
  `GET`      `/details`        Get all employees             None
  `GET`      `/details/{id}`   Get an employee by ID         None
  `PUT`      `/details`        Update an existing employee   Employee JSON
  `DELETE`   `/details/{id}`   Delete an employee by ID      None
  `DELETE`   `/details`        Delete all employees          None

### 1. Create an employee

**Request**

``` http
POST http://localhost:1521/details
Content-Type: application/json
```

``` json
{
  "name": "Rahul Kumar",
  "email": "rahul@example.com",
  "city": "Bangalore",
  "phno": 9876543210
}
```

**Successful response**

``` text
Data inserted successfully
```

The database generates the employee ID.

### 2. Get all employees

``` http
GET http://localhost:1521/details
```

Returns the list of employee records.

### 3. Get an employee by ID

``` http
GET http://localhost:1521/details/1
```

Returns the matching employee. If no record is found, the current
service returns a text message indicating that no data was found.

### 4. Update an employee

``` http
PUT http://localhost:1521/details
Content-Type: application/json
```

``` json
{
  "id": 1,
  "name": "Rahul Kumar",
  "email": "rahul.kumar@example.com",
  "city": "Mysore",
  "phno": 9876543210
}
```

The service checks whether the supplied ID exists and saves the
submitted employee data if it does.

### 5. Delete an employee by ID

``` http
DELETE http://localhost:1521/details/1
```

Deletes the employee if the ID exists.

### 6. Delete all employees

``` http
DELETE http://localhost:1521/details
```

**Warning:** This endpoint deletes every employee record in the table.
Use it carefully.

## Validation and Error Handling

The `Employee` entity uses validation annotations:

-   `@NotBlank` for `name`, `email`, and `city`.
-   `@Email` for email format.
-   `@NotNull` for `phno`.
-   `@Column(unique = true)` to enforce unique email values at the
    database level.

The controller applies `@Valid` to the create request.

`GlobalExceptionHandler` handles these cases:

  ------------------------------------------------------------------------------------------
  Exception                                                HTTP status Current response
                                                                       purpose
  --------------------------------------- ---------------------------- ---------------------
  `MethodArgumentNotValidException`                    400 Bad Request Returns field
                                                                       validation messages

  `HttpMessageNotReadableException`                    400 Bad Request Reports malformed or
                                                                       unreadable JSON

  `DataIntegrityViolationException`                       409 Conflict Reports duplicate
                                                                       values or
                                                                       data-integrity
                                                                       conflicts

  `MethodArgumentTypeMismatchException`                400 Bad Request Reports an invalid
                                                                       path parameter value

  Other `Exception`                          500 Internal Server Error Returns a general
                                                                       error response
  ------------------------------------------------------------------------------------------

Error responses include a timestamp, status code, error name, and
message.

## Security Note

Spring Security is included as a dependency. The current
`SecurityFilterChain` disables CSRF and permits all requests, so the API
endpoints are not authenticated by that configuration. Do not expose
this configuration as-is in a production environment. Add and test an
appropriate authentication and authorization strategy before deployment.

The `spring.security.user.*` properties in the original configuration do
not make these endpoints protected while the custom filter chain permits
every request.

## Current Implementation Notes

These details reflect the source code in this repository:

-   The API base path is `/details`.
-   The application port is `1521`.
-   The service uses constructor injection.
-   The repository extends `JpaRepository<Employee, Integer>`.
-   The create endpoint uses `@Valid`; the update endpoint currently
    does not.
-   The update operation saves the submitted employee object when its ID
    exists.
-   The get-by-ID and delete-by-ID service methods return text messages
    when an ID is not found.
-   The delete-all endpoint removes all employee records.
-   The project includes a Spring Boot test source file; the README does
    not claim that a full test suite has been executed.
